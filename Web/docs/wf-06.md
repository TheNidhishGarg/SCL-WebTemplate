# WF-06: Cinematic journey planning

WF-06 plans a cinematic journey as a **storyboard and a versioned scene manifest**. It's a standalone planning module: **no video is generated here, and none is needed** to plan, review, approve or export. WF-07 (video production) works from its scene manifest; WF-08 (the live visitor runtime, not built here) works from its journey spec.

## Where

| URL | What |
| --- | --- |
| `/projects/:id/journeys` | Journeys in the project; create from a template or the sample |
| `/projects/:id/journeys/:journeyId` | Storyboard editor, scene editor, goals, live checks, version history |
| `GET /api/projects/:id/journeys/:journeyId/scene-manifest` | `scl.wf-06.scene-manifest/v1` for **WF-07** |
| `GET /api/projects/:id/journeys/:journeyId/journey-spec` | `scl.wf-06.journey-spec/v1` for **WF-08** |

Both exports default to the **approved** version (404 if there is none). Use `?version=latest` or `?version=<n>` for drafts and older versions, and `&download` for a file.

## Model

Schema: [src/domain/journey.ts](../src/domain/journey.ts).

- **Goals:** objective, target audience, entry point (standalone, a WF-05 page, or a WF-05 page section), intended actions (the brief's desired actions), and success criteria (metric + target).
- **Format:** aspect ratio and target runtime. Templates prefill these from the brief's cinematic intent and runtime.
- **Scenes:** a graph with one start scene. Types:

  | Type | Rules |
  | --- | --- |
  | `opening` | exactly one, and the start |
  | `transition` / `information` | continue to one next scene |
  | `decision` | 2–6 **branches** (each a labelled choice), an optional timeout with a default branch, no single next |
  | `conversion` | continues to a next scene and must carry at least one **CTA** |
  | `ending` | no next; hands the visitor back to the site |

- **Per scene:**
  - narrative purpose, duration target and aspect ratio
  - visual description, subject, environment, lighting, mood, camera movement (+ notes)
  - continuity notes and the scenes it must match
  - **keyframes** (start/middle/end, referencing a WF-01 register image, a WF-02 screenshot capture or an https URL, with notes) and visual notes
  - **generation prompt** (positive and negative)
  - **asset slots** (video, loop, still or audio; required or optional)
  - transitions (cut, crossfade, match cut, whip pan, fade to black, continuous)
- **Stable IDs:** scenes, transitions, branches, CTAs, keyframes, asset slots and success criteria each have a UUID that never changes.

### Interface text never goes into footage

Branch labels and CTAs are data that WF-08 overlays as HTML, so they can be translated, read by screen readers and changed without regenerating video. Three things enforce this:
1. Every exported negative prompt includes *"no on-screen text, no captions, no subtitles, no logos rendered as text, no UI elements, no buttons, no watermarks"*.
2. Every asset slot's acceptance criteria include `noBurnedInText: true`.
3. A prompt that asks for text ("caption", "button", "title card", "says '…'") is flagged.

The manifest lists each scene's overlays (choices, CTAs, placement and timing), so footage can leave room for them.

## Checks

[src/domain/journey-validate.ts](../src/domain/journey-validate.ts) runs live in the editor and on the server; errors block approval.

| Check | Level |
| --- | --- |
| No scenes; no opening; more than one opening; no ending; start scene missing or not the opening | error |
| **Unreachable** scene (no path from the opening) | error; the board shows it under "Not connected" |
| **Invalid transition**: to a scene that doesn't exist, to itself, or back to the opening; branches on a non-decision; a next on a decision or ending; a non-ending that goes nowhere | error |
| Decision with fewer than 2 branches, an unlabelled branch, or a timeout defaulting to a missing branch | error |
| A loop that can never reach an ending | error |
| **Missing conversion path**: no path from the opening reaches a conversion scene | error |
| A branch whose path never reaches a conversion scene | warning |
| Conversion scene without a CTA; a CTA without a label, or linking to a WF-05 page or section that no longer exists | error |
| **Production readiness**: missing title, purpose, visual description, subject, environment, lighting, mood or prompt; no required video/loop slot; an unlabelled slot; continuity pointing at a deleted scene | error |
| Keyframe referencing an asset or capture not in this project | error |
| No keyframe yet; a decision without a loop slot; a prompt asking for text; a CTA appearing after its scene ends; the shortest path more than 25% off the target runtime; actions not in the brief | warning |

## Samples and templates

[src/domain/journey-samples.ts](../src/domain/journey-samples.ts):
- **Complete sample:** an architecture studio's site visit. It has an opening, a decision between homes and public buildings, two information scenes, a conversion and an ending, with every field filled. It passes every check and shows what "ready for production" looks like.
- **Branching template** and **linear template:** structurally valid graphs with the production details left blank, so the checks list exactly what to write.

## Versions

Versions work like the brand: edit a draft, **Approve** (blocked by errors), and **Start revision** opens the next version. The approved version stays the handoff until the revision is approved. Saves from a stale tab are refused.

## Contracts

Schemas: [src/domain/journey-contract.ts](../src/domain/journey-contract.ts).

### Scene manifest → WF-07

```jsonc
{
  "schema": "scl.wf-06.scene-manifest/v1",
  "project": { … }, "journey": { "id": "…", "key": "site-visit", "name": "…" },
  "version": { "number": 1, "status": "approved", "approvedAt": "…" },
  "format": { "aspectRatio": "16:9", "targetRuntimeSeconds": 60 },
  "brand": { "id": "…", "version": 1, "configPath": "/api/…/brands/…/config" },   // WF-04, for visual consistency
  "textPolicy": "No text, captions, UI or logos may be generated into footage. All interface text is overlaid by WF-08.",
  "scenes": [{
    "id": "…", "order": 0, "title": "…", "type": "opening", "purpose": "…", "durationSeconds": 12, "aspectRatio": "16:9",
    "visual": { "description": "…", "subject": "…", "environment": "…", "lighting": "…", "mood": "…", "camera": "dolly_in", "cameraNotes": "…" },
    "continuity": { "notes": "…", "matchesSceneIds": [] },
    "keyframes": [{ "id": "…", "label": "…", "position": "middle", "ref": { "kind": "asset", "url": "/api/…/assets/…/file" }, "notes": "…" }],
    "visualNotes": "…",
    "prompt": { "positive": "…", "negative": "…, no on-screen text, no captions, …" },
    "assetSlots": [{ "id": "…", "kind": "video", "label": "Main shot", "durationSeconds": null, "required": true,
                     "acceptance": { "aspectRatio": "16:9", "minDurationSeconds": 12, "seamlessLoop": false, "noBurnedInText": true } }],
    "overlays": [{ "kind": "cta", "label": "Talk to the studio", "placement": "beside", "atSeconds": 4 }]
  }],
  "issues": [ … ]
}
```

`order` is breadth-first playback order from the opening. WF-07 produces one asset per slot and reports it against the **slot id**.

### Journey spec → WF-08

```jsonc
{
  "schema": "scl.wf-06.journey-spec/v1",
  "…header": "…",
  "goals": { "objective": "…", "audience": "…", "intendedActions": ["lead_form"], "successCriteria": [ … ] },
  "entryPoint": { "kind": "page_section", "pageId": "…", "sectionId": "…", "path": "/" },
  "fallback": { "path": "/contact", "reason": "Shown when the journey cannot play …" },
  "startSceneId": "…",
  "scenes": [{
    "id": "…", "order": 1, "type": "decision", "title": "…", "durationSeconds": 10, "slotIds": ["…"],
    "next": null,
    "choice": { "branches": [{ "id": "…", "label": "Homes", "to": "…", "style": "crossfade", "durationMs": 600 }], "timeout": { "seconds": 20, "defaultBranchId": "…" } },
    "ctas": []
  }],
  "endingSceneIds": ["…"], "conversionSceneIds": ["…"], "issues": [ … ]
}
```

- **Same IDs in both exports:** scene, slot, branch and CTA ids are identical, so WF-08 plays WF-07's asset for slot X at scene Y without guessing.
- **Paths through WF-05:** CTA targets and the entry point are resolved to WF-05 paths (`/contact`, `/#s-<sectionId>`). Their page and section ids are kept, so WF-08 can link to the published site.
- **Fallback:** a conventional page for visitors who can't or won't play the journey. **The conventional site must work without it.**

## Limitations

- **The visitor runtime is not built here.** Playback, preloading, reduced-motion handling and analytics are WF-08 and WF-09.
- **No video and no automatic keyframes.** Keyframes are references people attach.
- **The storyboard is a step-by-step board, not a free-form canvas.** Scenes are placed by their distance from the opening, so the layout always matches the graph.
- **One aspect ratio per scene.** Producing multiple formats is WF-07's decision.
- Same access model as WF-01: no sign-in yet.
