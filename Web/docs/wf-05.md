# WF-05: Content and page generation

WF-05 builds the **conventional website**: a sitemap and pages made of structured content, edited in the dashboard, reviewed, published, and rendered by shared Next.js components with the WF-04 brand. It works without any cinematic journey, and contains no AI video or journey orchestration.

## About "SCL CMS"

Neither this repository nor this machine contains SCL CMS code or an API description, so **no CMS API is assumed or invented**. Content lives in this app's own store ([src/server/store/content.ts](../src/server/store/content.ts)), behind the same boundary as the other modules. If SCL CMS becomes available, an adapter replaces that one module: the content model, editor, renderer and manifest stay the same. Before building that adapter, someone needs to confirm what SCL CMS can store (structured sections? media?) and how it authenticates.

## Where

| URL | What |
| --- | --- |
| `/projects/:id/pages` | Sitemap, site settings (name, address, language, brand), generation, new pages, reusable blocks |
| `/projects/:id/pages/:pageId` | Page editor with live checks and the review workflow |
| `/preview/:projectId/…` | **Preview environment**: the latest content of every page, never indexed, with a banner |
| `/site/:projectId/…` | **Published site**: published snapshots only, with the approved brand |
| `GET /api/projects/:id/content/manifest` | The content manifest for WF-08/09 |

## Content model

Schema: [src/domain/content.ts](../src/domain/content.ts). Content is data only, with no markup, classes or styles:

- **Page**: `slug` (empty for home; `work/case-studies` allowed), `title`, `navLabel`, `inNav`, `inFooter`, `layout` (`standard | landing | article`), `templateRef` (a WF-03 manifest template id), `seo` (`title`, `description`, `canonicalPath`, `noindex`, `ogImage`), `sections[]`.
- **Sections**: `hero`, `text`, `features`, `gallery`, `faq`, `cta`, `contact`, and `block` (a reference to a **reusable block**: edit it once and every page using it changes).
- **Media**: `{ id, source: asset (WF-01 register) | https url, alt, decorative }`.
- **CTA**: `{ id, label, style, target: page | page section | url (https, mailto, tel), actionKind }`. `actionKind` ties a button to a WF-01 desired action, for WF-09.
- **Navigation**: derived from page order plus `inNav`/`inFooter`, so it cannot drift from the pages it lists.
- **Site settings**: `siteName`, `baseUrl` (for canonical URLs), `brandId` (a WF-04 brand **in this project**), `locale`.

Every page, section, item, media entry and CTA has a **UUID assigned once and kept across edits**.

## Generation from the brief

**Generate sitemap and drafts** creates one page per required page in the approved WF-01 brief. It's re-runnable, and existing paths are left alone. It uses only what the brief says: page titles, purposes and desired actions. Every piece of copy, including button labels, is a `[Write: …]` placeholder.

- **Home page:** a hero, a features list of the other pages, and a closing CTA.
- **Contact-like page:** a contact section tied to the first desired action.
- **Other pages:** a hero, a text section and a CTA.
- **CTAs:** they point at the contact page.

Placeholders are incomplete content: **a page containing one cannot be submitted for review or published.** Nothing generated reaches the published site without a person writing it and approving it.

## Workflow

```
draft ──submit──► in_review ──approve──► approved ──publish──► published
  ▲                  │ return                                     │
  └──────────────────┴──── any edit sends the page back to draft ─┘
```

- **Submit** and **approve** require no validation errors. **Publish** additionally requires the site's brand to have an approved WF-04 version, and every internal link to point at a page that is published.
- Publishing **freezes a snapshot** (`published_content`, `published_revision`). Editing a published page sends it back to draft, but the live snapshot stays until the page is published again. **Unpublish** takes it off the site.
- Saves carry the revision the editor loaded; a stale save is refused.

## Validation

[src/domain/content-validate.ts](../src/domain/content-validate.ts) runs live in the editor and on the server with the same code.

**Errors** (block submission and publication):
- placeholders left in
- missing required content (hero heading, text body, features/FAQ items, CTA heading and buttons, a way to get in touch)
- SEO title or description missing
- a duplicate path
- **broken links** (to a deleted page, or a section anchor that no longer exists)
- **missing assets** (not in this project's register)
- images without alt text and not marked decorative
- a missing reusable block
- *at publish:* links to unpublished pages, no brand, or an unapproved brand

**Warnings:**
- an SEO title over 60 characters
- a short description
- more than one hero
- no site address set (canonical URLs then can't be absolute)

External URLs are not fetched; their reachability is WF-10's job.

## Rendering

[src/site/render.tsx](../src/site/render.tsx) holds the shared presentation components, and [src/app/(site)/site.css](../src/app/(site)/site.css) the styles.

- **Brand:** every visual value is a `--scl-*` variable from WF-04, applied to the page wrapper (`data-scl-brand`), with neutral fallbacks. Reduced motion follows the brand's rule. Changing the brand restyles every page; content edits never touch components.
- **Accessible structure:**
  - a skip link and `header`, `nav` ("Main"/"Footer"), `main` and `footer` landmarks
  - exactly one `h1` (the first hero's heading, otherwise the page title), with h2 for sections and h3 for items
  - `aria-current` on the active link, alt text from content, `lang` from site settings, and visible focus
- **Plain-text content.** Content is rendered as plain text (paragraphs split on blank lines), so it can't inject markup.
- **Responsive without hard-coded breakpoints:** grids use `auto-fit`/`minmax` and headings use `clamp()`. Tested at 375px and 1280px with no horizontal scroll.
- **SEO:** title, meta description, canonical URL (`baseUrl` + `canonicalPath` or the page path), Open Graph, and `noindex` (previews are always `noindex`).
- **Images** from the register are served by `/api/projects/:id/media/:assetId`. Only image types are served there, with a sandboxing Content-Security-Policy so even an SVG opened directly cannot run script.

## Contract for WF-08 (and WF-09)

`GET /api/projects/:id/content/manifest` returns `scl.wf-05.content-manifest/v1`. Schema: `ContentManifest` in [src/domain/content-manifest.ts](../src/domain/content-manifest.ts).

```jsonc
{
  "schema": "scl.wf-05.content-manifest/v1",
  "project": { "id": "…", "slug": "…" },
  "site": {
    "siteName": "…", "baseUrl": "https://…", "locale": "en-IN",
    "brand": { "id": "…", "version": 1, "configPath": "/api/…/brands/…/config", "cssPath": "/api/…/brands/…/css" },
    "publishedRoot": "/site/<projectId>", "previewRoot": "/preview/<projectId>"
  },
  "navigation": { "primary": [{ "pageId": "…", "label": "Home", "path": "/" }], "footer": [ … ] },
  "pages": [{
    "id": "…", "path": "/", "canonicalUrl": "https://…/", "title": "Home", "layout": "landing", "templateRef": null,
    "status": "published", "revision": 4, "published": { "revision": 4, "at": "…" },
    "sections": [{ "id": "…", "type": "hero", "anchor": "s-<id>", "blockId": null }],
    "media": [{ "id": "…", "sectionId": "…", "source": { "kind": "asset", "assetId": "…" }, "alt": "…", "decorative": false }],
    "ctas": [{ "id": "…", "sectionId": "…", "label": "…", "actionKind": "lead_form", "target": { "kind": "page", "pageId": "…" } }],
    "content": { /* PageContent, latest revision */ },
    "issues": [ … ]
  }],
  "blocks": [{ "id": "…", "name": "…", "section": { … }, "usedBy": ["<pageId>"] }]
}
```

The rendered HTML carries the same ids:

| Attribute | On |
| --- | --- |
| `data-scl-page-id`, `data-scl-revision`, `data-scl-brand` | page wrapper |
| `data-scl-section-id`, `data-scl-section-type`, `data-scl-block-id`, `id="s-<sectionId>"` | each section |
| `data-scl-item-id` | feature and FAQ items |
| `data-scl-media-id` | images |
| `data-scl-cta-id`, `data-scl-action` | buttons |

WF-08 should place journey entry points by **section id** (or anchor), never by text or position. WF-09 should attach tracking and forms by `data-scl-cta-id` / `data-scl-action` and the contact section's `actionKind`. Read `published.revision` to know what is live.

## Limitations

- **Text is plain**, with no inline formatting (bold, inline links) yet. Adding a constrained rich-text format is a model change, not a component hack.
- **Templates are not yet applied.** `templateRef` records which WF-03 template a page follows, but the renderer does not yet apply extracted templates. The three layouts are built-in.
- **No forms.** Contact sections mark where the WF-09 form will go.
- **No hard locking.** Published and preview routes use the same access rule as the dashboard (no sign-in yet). Making the published site public is WF-10's deployment decision.
- **Fonts aren't loaded** (see WF-04): pages use installed fonts or fallbacks.
- **Content isn't localised:** one language per site.
