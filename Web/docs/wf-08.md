# WF-08: Interactive journey integration and composite website

WF-08 puts the two tracks together as one website:

- the conventional pages (WF-05)
- the cinematic journey: the approved plan from WF-06 and the approved media from WF-07

Both render in **one site shell**, with the same header, navigation, footer and brand tokens (WF-04). A journey plays through a reusable runtime: a pure **Journey Controller** plus a **player** that uses GSAP for motion. The runtime reads one input, a versioned **journey bundle**. It knows nothing about AI providers, projects or the CMS.

## Where

| URL | What |
| --- | --- |
| `/site/:projectId/journeys/:key` | The live journey (newest release that hasn't been withdrawn), inside the site shell |
| `/preview/:projectId/journeys/:key` | The approved journey assembled now, with whatever media is approved so far. Never indexed. Shows assembly notes. |
| `/site/:projectId/…` (entry page) | A "Start the journey" launcher on the journey's entry page or section. It's a plain link, so it works without JavaScript. |
| `/projects/:id/production/:productionId` → **Website (WF-08)** | Assembly checks, preview, publish, withdraw, and the release history |

The `/journeys` path is reserved: pages can't use it as their path (enforced by page validation).

## Contracts in, bundle out

Assembly ([src/server/store/experience.ts](../src/server/store/experience.ts)) reads only approved inputs:

| Input | Used for |
| --- | --- |
| `scl.wf-06.journey-spec/v1` (approved version) | Scenes, their order, the start scene, next transitions, branches, decision timeouts, CTAs (all by their stable IDs), entry point |
| `scl.wf-06.scene-manifest/v1` | Aspect ratio |
| `scl.wf-07.asset-manifest/v1` (the production for *that* journey version) | Approved video or loop take per scene, an approved still as the poster, blocked reasons |
| WF-05 pages (published snapshots, or the latest content in preview) | CTA links (page or section), the exit and fallback page, the launcher location |
| WF-04 brand | Through the site shell: the journey uses the same `--scl-*` tokens as the pages |

The output is `scl.wf-08.journey-bundle/v1` ([src/runtime/journey/bundle.ts](../src/runtime/journey/bundle.ts)). It contains:

- scenes with `video` (src, type, size, duration, SHA-256) or none, `loop`, `poster`, `next`, `choice` (branches and timeout) and `ctas` (resolved `href`s)
- the start scene and the aspect ratio
- `entry`: where the launcher goes
- `exit`: where visitors go when they finish, leave, or the journey can't play
- `sources`: which contract versions it was built from

It has **no provider, model or prompt fields**. A unit test checks this.

**Validation happens twice:** once when publishing (assembly), and again every time the site serves a release (`checkBundle`).

- Links must be site-relative paths or `https:`, `mailto:` or `tel:` (no `javascript:` and no protocol-relative URLs).
- Media must be same-origin paths or `https:`.
- Every destination, start scene and default branch must exist.
- Assembly also checks that every media URL is an **approved take of this journey version's production** with a matching SHA-256.

**Publishing is refused when:**
- a scene has neither approved footage nor an explicit block
- a CTA links to an unpublished page or a removed section
- no page is published for visitors to fall back to
- the bundle is invalid

**Blocked scenes** are allowed, with a warning, and play as **title cards**: the poster if there is one, otherwise the brand gradient. Every control still works on a title card.

**Releases** are numbered and frozen. Editing pages or the journey afterwards doesn't change a live release; publishing again creates release *n+1*. **Withdraw** takes the journey off the site. Its URL then shows "This journey isn't available right now" with a link to the website, and the launcher disappears.

## Runtime

Everything under [src/runtime/journey/](../src/runtime/journey/) is project-independent.

### Controller (`controller.ts`)

A pure state machine with no DOM and no `<video>`.

- **Statuses:** `intro`, `running`, `finished`, `exited`
- **Playback phases:** `loading`, `playing`, `buffering`, `paused`, `blocked` (autoplay refused), `ended`, `failed`, `still` (title card)
- **Events it accepts:**
  - media: `playing`, `waiting`, `time`, `ended`, `error`, autoplay refusal
  - visitor: start, resume, play, pause, retry, choose, skip, back, restart, leave
  - timer: the decision timeout
- **What it tracks:** history (for Back), the path visited (progress), the transition to run, and whether the visitor or playback caused a scene change (used for focus handling).
- **Rules:**
  - A decision scene can't be skipped; the visitor must choose.
  - A looping scene never "ends".
  - A failed scene keeps its choices and shows its CTAs immediately.
  - A destination can be a scene or a page. WF-06 currently only produces scene branches; pages are reached through CTAs, the exit, and the end of the journey.

### Player (`player.tsx`)

**Playback and errors**
- Plays one `<video>` per scene (`playsInline`, `preload="auto"`). The video is `aria-hidden`: it's decoration, and all meaning is in the HTML around it.
- **Autoplay:** **Start** is a user gesture. If playback with sound is refused, the player retries muted. If that's refused too, it shows "Your browser paused the film. Press Play to continue".
- **Buffering:** a "this is taking a while" notice appears after 8 seconds, and **Next scene** is always available.
- **Errors:** the scene becomes a title card with an alert and **Try again**. The choices, CTAs, Next scene and **Leave the journey** links all keep working. In preview, the media error detail is shown.
- **Hidden tab:** playback pauses.

**Progress**
- Progress is kept in `sessionStorage` for the tab and offered as **Resume where you left off**. If storage is unavailable, the player works without it.

**Interface text**
- Everything a visitor reads or uses is HTML: the scene title (an `h2`, used as the caption line), choices (buttons in a labelled group), CTAs (links with `data-scl-cta-id` and `data-scl-action`), the decision countdown with **Wait, I'll choose**, the controls, the path list, and an `aria-live` status line. None of it is in the footage; WF-06/WF-07 keep text out of the footage.

**Focus**
- When the visitor causes a scene change, focus moves to the new scene's heading, so it's never lost on a removed button.
- Scene changes caused by playback never steal focus.
- Every control is a native button or link, at least 44 px.

**Motion (GSAP)**
- Scene entrances by transition style:
  - `crossfade` and `continuous`: a fade-in from the stage background (not a true two-video crossfade)
  - `fade_to_black`: through a black curtain
  - `whip_pan`: a short slide-and-blur
  - `cut` and `match_cut`: instant
- Overlays stagger in.

**Reduced motion** (`prefers-reduced-motion: reduce`)
- GSAP isn't used at all: cuts only, with no inline animation styles.
- Looping footage stays on its first frame until **Play**.
- The intro says so.

**Mobile**
- Below 640 px wide, the interface sits **below** the footage instead of over it.
- Buttons go full width, and there's no horizontal scroll.

**Configuration**
- `JourneyPlayer({ bundle, root, labels?, debug? })`
- `root` is the site prefix that site-relative links resolve against.
- `labels` replaces any interface string (e.g. for another language).
- A second project needs no code change: a different bundle and root are enough. The e2e test runs a second project with a different brand and no footage at all.

## Fallbacks

The conventional site never depends on the journey:
- Pages render without it.
- Launchers are plain links, and a launcher failure is caught and logged, not shown.
- A journey URL without a playable release still renders the site shell with a link to the website.
- With JavaScript off, a `<noscript>` link points to the website.
- Inside the player, **Skip the film** and **Leave the journey** are always present, and finishing ends with **Continue to {page}**.

## Not built, or not proven

- **Captions:** WF-06 has no narration or dialogue field, so there's no caption track. The scene title is shown as HTML. If footage has speech (Veo can generate audio), the plan needs a transcript field before captions can be produced.
- **Forms:** CTAs link to the page or section with the form. The forms themselves are WF-09, so a "lead form" CTA currently opens the contact section, not a form.
- **Public hosting:** the site routes, including media, are served by this app under the same access rule as the dashboard (as in WF-05). Public hosting and a CDN for video are deployment work.
- **Browsers:** e2e tests run in Playwright's Chromium only, desktop and a 390 px viewport. Safari and iOS (stricter autoplay and inline playback) and Firefox weren't tested. Real devices weren't tested.
- **Autoplay refusal:** covered by controller unit tests, not e2e, because Playwright's Chromium allows autoplay.
- **Preloading:** there's none beyond the browser default. The next scene starts loading when it's entered.

  - mobile layout

  - withdraw and fallback
