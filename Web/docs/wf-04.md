# WF-04: Brand configuration and design tokens

WF-04 turns brand decisions into a **versioned, validated configuration**, exported as JSON and as CSS custom properties. WF-05 to WF-08 build from it. It does not write content or generate video.

## Where

`/projects/:id/brands` lists a project's brands; a project can hold several, such as a parent brand and a sub-brand. `/projects/:id/brands/:brandId` holds the editor, live preview, checks, version history and exports.

## Every value records how sure we are

Each design value is a token: `{ value, status, note }`.

| Status | Meaning |
| --- | --- |
| `confirmed` | Stated by the client or their guidelines (typing a value marks it confirmed) |
| `inferred` | Derived from evidence; `note` says where (e.g. `Client site: --brand (css/site.css:1)`) |
| `default` | A neutral starting value nobody has decided on |
| *missing* | `value: null` |

A new brand starts from accessible neutral defaults, all marked `default`. Heading and body fonts and the primary logo start missing, because no default can stand in for them.

**Suggest from client's own material** fills values that are still `default` or missing, and marks them `inferred` with their source. It uses only:
- logos from the client's WF-01 asset register, and
- custom properties, fonts and breakpoints from WF-03 sources marked **client-owned**.

It never uses study-only references (other people's brands), and never overwrites a confirmed or already-inferred value. WF-02 visual-style notes are shown beside the editor as context only.

## What the configuration covers

| Group | Tokens |
| --- | --- |
| Colours | primary, onPrimary, secondary, accent, background, surface, text, textMuted, border, success, warning, danger, info (6-digit hex) |
| Typography | heading/body/mono families (with fallback and source), regular/medium/bold weights, base size, scale ratio, body/heading line height, body/heading/caps letter spacing |
| Layout | spacing unit, content width, narrow width, grid columns and gutter, breakpoints sm/md/lg/xl |
| Shape | radius sm/md/lg, shadow sm/md/lg |
| Motion | fast/base/slow duration, easing, intensity, and how reduced motion is honoured (`shorten` to 1ms or `remove` to 0ms; it is always honoured) |
| Assets | logos (variant, background, minimum width), images (role), icon library and style. Each points at a WF-01 register entry **of the same project**, or an https URL. |

Schema: `BrandContent` in [src/domain/brand.ts](../src/domain/brand.ts).

## Validation

Validation runs live in the editor and again on the server, with the same schema. Errors appear at the field and say how to fix them, for example: *"Use a 6-digit hex colour, e.g. #1A2B3C"*, *"Must be at most 24px"*, *"Must be larger than the sm breakpoint (640px)"*, *"Must be narrower than the content width (1200px)"*. An invalid value is never saved.

Every value that reaches CSS is restricted to a plain literal: hex colours, bounded numbers, family names of letters, digits, spaces and hyphens, a strict box-shadow grammar, and easing keywords or `cubic-bezier()`. A configuration cannot inject CSS into the pages that use it.

## Accessibility checks

WCAG 2.2 AA contrast is checked live:

| Blocks approval | Warns |
| --- | --- |
| text/background, text/surface, onPrimary/primary, textMuted/background, danger/background at 4.5:1; primary/background at 3:1 | accent/background 3:1, border/background 3:1 (WCAG 1.4.11), success/warning/info on background 4.5:1 |

Each failure gives the ratio, what it is for, and which colour to darken or lighten. Other checks:
- Warnings: body text under 16px; body line height under 1.5; long expressive motion.
- Errors (block approval): any required value missing; no primary logo.

## Versions

Versions work like the brief. You edit a draft; **Approve** saves, re-validates and freezes it, and requires no blocking issues. **Start revision** opens version n+1 as a draft, and the approved version remains the handoff until the new one is approved. History lists every version with its JSON and CSS. A save from a stale tab is refused.

## Isolation

- Every read and write is scoped by project. A brand id from another project returns not found, in pages and in the API.
- Asset references must be entries in the **same** project's register; anything else is refused at save.
- The live preview applies variables inline to its own container (`data-scl-brand="<key>"`), never to the page, so a brand cannot restyle the dashboard or another brand. This is tested.
- Scoped CSS (`?scope=brand`) wraps the variables in `[data-scl-brand="<key>"]`, so several brands can share a page.

## Handoff to WF-05, WF-06, WF-07 and WF-08

| Endpoint | Returns |
| --- | --- |
| `GET /api/projects/:id/brands/:brandId/config` | `scl.wf-04.brand-config/v1` JSON for the **approved** version (404 "No approved version yet." if there is none) |
| `GET …/config?version=latest` or `?version=<n>` | The same for the latest draft or a specific version |
| `GET …/css` | CSS custom properties on `:root` |
| `GET …/css?scope=brand` | The same, scoped to `[data-scl-brand="<key>"]` |

Add `&download` to either for a file. Schema: `BrandExport` in [src/domain/brand-contract.ts](../src/domain/brand-contract.ts).

```jsonc
  "reducedMotionVariables": { "--scl-duration-fast": "1ms", "…": "…" },
  "breakpointsPx": { "sm": 640, "md": 768, "lg": 1024, "xl": 1280 },
  "scopeSelector": "[data-scl-brand=\"acme\"]",
  "provenance": { "confirmed": ["colors.primary"], "inferred": [], "default": ["colors.secondary"], "missing": ["typography.mono.family"] },
  "issues": [{ "path": "colors.warning.value", "level": "warning", "message": "…" }],
  "contrast": [{ "fg": "text", "bg": "background", "ratio": 17.4, "min": 4.5, "passes": true }],
  "assets": [{ "use": "logo:primary:any", "status": "confirmed", "note": "", "location": { "kind": "asset", "assetId": "…", "url": "/api/projects/…/assets/…/file" } }]

```

### CSS variables

All are prefixed `--scl-`:
- `color-<role>` (kebab-case, e.g. `color-on-primary`, `color-text-muted`)
- `font-heading|body|mono`, `font-weight-regular|medium|bold`
- `font-size-xs|sm|base|lg|xl|2xl|3xl|4xl`: base × ratioⁿ for n = −2…5, in rem, 4 dp
- `line-height-body|heading`, `letter-spacing-body|heading|caps`
- `space-0…10`: unit × 0, 1, 2, 3, 4, 6, 8, 12, 16, 24, 32 px
- `content-width`, `content-width-narrow`, `grid-columns`, `grid-gutter`, `breakpoint-sm…xl`
- `radius-sm|md|lg|pill`, `shadow-sm|md|lg`
- `duration-fast|base|slow`, `easing-standard`, `motion-enabled`

Under `@media (prefers-reduced-motion: reduce)` the durations become 1ms (`shorten`) or 0ms (`remove`). **A missing value emits no variable**: it is listed in a comment and in `provenance.missing`, so consumers should write `var(--scl-x, fallback)`.

The CSS and JSON come from the same function as the live preview (`brandVariables` in [src/domain/brand-css.ts](../src/domain/brand-css.ts)). Tests check that the exported CSS equals `cssVariables`, name for name.

### How consumers should use it

- **WF-05 (pages):** link the CSS, or inline `cssVariables`. Use `breakpointsPx` for media queries, since custom properties do not work inside `@media`. Resolve logos through `assets[].location`.
- **WF-06/07 (journey, video):** colours, `motion.*`, `typography` and logos for titles and overlays. Respect `motion.intensity` and the reduced-motion rule in any interactive playback.
- **WF-08 (integration):** use the scoped CSS when more than one brand or the dashboard shares a page.
- **Everyone:** use the **approved** version, record `brand.id` + `version.number` on what you produce, and treat `provenance.inferred`/`default` as not yet signed off by the client.

## Limitations

- Fonts are not loaded in the preview: families render only if installed on the viewer's computer, otherwise the fallback shows. Font licensing is a WF-03/WF-01 question, not checked here.
- Contrast is checked for defined colour pairs, not for every combination a page might use.
- Colours are 6-digit hex only (no alpha, no other colour spaces).
- No dark-mode variant set yet: one palette per brand version.
- Same access model as WF-01: no sign-in yet.
